# Love-is-pure-white Constitution

## Core Principles

### I. Python 3 运行环境

项目应用代码必须使用 Python 3 运行。实施前必须声明受支持的 Python 版本范围，
并固定开发使用的具体版本；所选版本必须同时满足 LangChain 与 QQ 接入依赖的兼容要求。
开发、测试和运行必须遵循同一版本约束，避免环境差异导致行为不一致。

### II. uv 环境与依赖管理

必须使用 uv 创建项目本地虚拟环境 `.venv`，应用运行与测试必须使用该环境。
项目依赖必须通过 uv 管理，在 `pyproject.toml` 中声明并通过 `uv.lock` 锁定。
依赖变更必须同步更新声明与锁文件；禁止以全局安装或未声明的本地依赖作为运行前提。
虚拟环境目录不得提交到版本控制，以保证环境可重建。

### III. LangChain 大模型开发框架

大模型调用与应用编排必须以 LangChain 为框架。模型供应商、模型名称及认证信息
必须通过配置提供，禁止在聊天入口中硬编码供应商调用逻辑或密钥。
模型调用能力必须能够脱离 QQ 入口独立调用和验证，以便定位问题并支持后续扩展。
不要求在实际需求出现前引入 Agent、向量数据库或其他模型能力。

### IV. QQ 优先的聊天入口与职责分离

现阶段必须以 QQ 聊天作为用户消息输入入口。QQ 消息接收、消息格式转换和回复发送
必须封装在入口适配层；对话处理及 LangChain 调用必须与 QQ 平台协议分离。
当前阶段不得将其他聊天平台作为交付前提。QQ 是阶段性选择，新增或替换入口时
必须明确需求和验收范围，并保持对话处理接口的独立性。

### V. 腾讯 QQ 机器人官方规范优先

QQ 机器人必须通过腾讯 QQ 机器人开放平台提供的正式能力开发，并遵循
[腾讯 QQ 机器人官方文档](https://bot.q.qq.com/wiki/)及其链接的现行开发与运营规范。
鉴权、事件接收与校验、消息收发、权限申请、频率限制和发布流程，必须以对应场景的
官方规定为依据。第三方 SDK 或示例不得替代官方接口契约；禁止以个人 QQ 账号模拟登录、
逆向协议或绕过平台限制的方式实现机器人能力。

涉及 QQ 平台能力的规划与变更，必须记录使用的官方文档链接、查阅日期和适用场景，
并核对实际应用已获授权的能力。需求与官方能力冲突时，必须记录差异并调整方案；
未经支持或尚未获权的能力不得宣称可用，以保证实现可接入、可验证且可持续维护。

## 技术约束

- 技术基线为 Python 3、uv、LangChain 和 QQ 聊天入口。
- 具体 Python 3 次版本、LangChain 版本、模型供应商及 QQ 接入方式，必须在相关
  功能规划中确定并记录依据；本宪章不预设尚未确认的协议或 SDK。
- QQ 凭据、模型 API 密钥与其他认证信息必须由环境变量或运行时配置注入，
  禁止提交真实凭据；日志不得输出密钥或认证令牌。
- 外部平台与模型调用失败必须形成可诊断的错误信息；面向用户的错误回复不得包含凭据。
- QQ 接入方式和所选 SDK 必须符合官方文档与应用权限；官方未承诺的能力不得作为交付前提。
- 延迟心理独白及其他延迟或主动消息，必须在规划时核对对应场景的发送条件、
  回复时效、消息类型与频率限制；不满足平台条件时不得绕过限制发送。

## 开发与验收流程

- 功能规格必须定义 QQ 输入范围、预期回复行为和失败场景。
- QQ 相关实施计划必须附官方文档依据及查阅日期，核对应用场景、接入权限、
  鉴权与事件处理要求、消息发送约束和测试环境条件；发布前重新核对相关规定。
- QQ 相关验收必须覆盖所用官方接口契约、认证或事件校验失败、权限不足及限流等
  实际适用的失败路径；官方测试环境与真实联调结果必须和替代服务验证结果区分记录。
- 实施计划必须核对本宪章，明确运行版本、依赖、入口适配层与对话处理层的边界。
- 环境交付必须验证可通过 uv 从依赖声明和锁文件重建虚拟环境并运行应用。
- 涉及聊天链路的变更必须验证消息接收、对话处理、回复发送及外部调用失败路径。
  自动化验证必须支持替换外部 QQ 与模型服务，避免依赖真实账号或付费调用。
- 交付审查必须记录实际执行的验证及结果；未执行的真实服务联调必须明确标注。

## Governance

本宪章是项目技术选择与开发约束的依据。规格、计划和实现审查必须检查合规性；
存在冲突时必须在实施前修订方案，或由项目维护者批准宪章修订。

修订必须记录修改原因、受影响的原则与迁移影响，由项目维护者审阅批准后生效。
每次修订必须更新版本和最后修订日期，保留首次批准日期。
版本采用语义化规则：不兼容的原则删除或重定义升级 MAJOR，新增原则或实质扩充
升级 MINOR，仅澄清措辞或修正错误升级 PATCH。

首次宪章根据项目维护者本次提供的技术基线建立。后续功能可以细化配置与实现选择，
但不得绕过已确定的 Python 3、uv、LangChain 和当前 QQ 入口约束。
