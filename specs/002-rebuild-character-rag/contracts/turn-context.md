# 每轮角色资料使用契约

## 调用边界

现有 QQ 适配层仍负责入站验签、去重及发送。DialogueTurnService 依次处理：用户与历史 → 固定活动包及策略 → 适用性检查 → 有证据的状态转换 → 条件选卡与检索 → 预算检查 → LangChain 生成 → 输出检查 → 既有发送与结算。

`FrozenTurnContext` 的版本引用连同 calibration_id/report_hash 一经确定不得再读取 active 来加载常驻、catalog、阈值或示例。缓存按 index_id 和 bundle_hash 定位；清理活跃缓存不能让旧在途引用失效。

## 输入

- 当前文本、历史（最多最近六轮）、最近三条用户输入用于补充查询。
- 既有用户与会话身份、relationship_status、scene，medium 默认为 text，物理地点未知。
- 前态、前次转换证据、维护者显式状态设置、已确认当前用户事实。
- 固定包、常驻、已批准条件和状态目录、编码配置。

范围中无新长期记忆抽取模块。未知 location/cohabitation/nickname 保留未知，不因同一 QQ 会话就假设物理同处。

## 状态与条件

- 复用四主心情，二级状态由批准目录映射六状态与吃醋三级。
- 事件提取扩展为当前文本加历史引用及 previous_state；模型只提事件和证据，不直接写 relationship、好感或目录。
- reducer 必须执行 from_states、关系/场景守卫和 exit_conditions，处理安抚后的恢复；已有未执行字段本次须补实现和测试。
- private 条件只接受明确 private；public-only 条件只接受明确 public；unknown 两者都不满足，但通用规则仍可用于保守表达。
- 恋人包与 non_romantic 冲突返回 package_relationship_mismatch，不调用正常角色生成、不覆盖账本。
- 公共场合可采用通用吃醋规则的收敛表达，不能选仅独处的委屈外露或安心依赖卡；不能把整张情绪卡是否可选等同每个动作可执行。

## 选择顺序与预算

1. 必须载入三份常驻，记录 resident IDs，不参与相关度竞争。
2. 当前有效状态对应的完整状态卡、相关场景规则按批准条件选取，不能因向量低分遗漏必要状态或恢复。
3. 背景与示例先条件过滤再相关排序；完整示例最多 2 张，补充引用总数上限沿用 8，多个来源不得伪造单一说话者。
4. 示例及背景整体不能覆盖常驻规则。背景较低、示例更低；预算不足按排序整卡排除并记录 budget_excluded；必要行为规则、常驻和本轮消息不得裁剪。
5. 必要内容超生成容量返回 context_over_limit；历史仅按完整旧轮次移除，查询按完整较早消息移除，不删恢复证据后继续假定状态有依据。

## 结果语义

- `ready_with_references`：规则有效且有相关补充内容，正常生成。
- `ready_without_references`：规则有效但补充为空或低于门槛，仍正常生成；具体未知事实应承认未知或询问，不泛化为所有聊天都不理解。
- `ambiguous_reference`：规则仍有效，排除冲突参考并保守回复，记录歧义。
- `package_unavailable` / `package_relationship_mismatch`：受控失败，不无约束生成。
- `processing_error`：编码或存储等异常单独处理，不换标签冒充低相关；模型、审核或发送失败亦分阶段记录。

以上为新格式结果，旧 semantic_v1 仍可沿原匹配决策路径运行。首轮启用前须验证配置加载与就绪检查正确分发。

## 生成约束与审核

系统级角色配置来自批准包的完整常驻和适用行为规则，不从任意检索结果提取命令。背景和示例带类型、来源、条件及示例性质，按引用传入，不当执行指令。用户消息保持用户角色；示例中的用户台词不提升到真实历史。

输出检查覆盖第一人称、句末无句号、禁区、代写用户动作与台词、示例事件当记忆、默认物理同处等。确定格式用规则检查，语义风险沿用受约束审核并扩展类别；自然性与状态连续性通过固定对话人工评分。审核不通过按既有重试上限和受控失败处理，不无限重试或发送违规内容。

## 诊断与能力

每轮记录 index/bundle/policy/catalog 版本、resident IDs、状态转换证据、候选和排除原因、预算处理、生成审核及发送结果，不记录凭据和完整系统提示。遵守现有日志正文保留规则。

新包无独白素材，独白机会创建前即因 disabled_no_material 跳过；规则、说明和示例续行不能被当作心理独白。角色主动分享只在现有调用机会中发生，本功能不建立后台主动发送服务。
