## User Scenarios & Testing *(mandatory)*

### User Story 1 - 从整理版设定建立可核对的资料库 (Priority: P1)

维护者将已整理的多文件角色设定作为一套资料导入，核对常驻规则、情绪卡、场景卡、背景和示例的归属及来源，获得可用于聊天的新资料版本。

**Why this priority**: 现有文档语义切分无法直接表达整理版的完整规则块和加载层次；先保证资料没有丢失或误分类。

**Independent Test**: 不接入聊天平台，导入当前整理版目录，核对两份完整常驻文件、26 个有标识的卡片及排除材料，验证全部内容都可回溯。

**Acceptance Scenarios**:

1. **Given** 当前整理版目录包含 00 至 07 共八份文件，**When** 维护者建立新资料版本，**Then** 01 和 02 作为常驻资料，03 中状态总则作为常驻规则，其余情绪卡及 04 至 06 卡片按类型保留；00 和 07 不进入角色对话内容。
2. **Given** 吃醋卡包含三级表现与恢复机制，示例包含多角色多轮对话，**When** 导入，**Then** 每张卡完整保留，不拆散恢复条件，不混淆示例说话者或丢失续行台词。
3. **Given** 某卡缺少必要字段、标识重复或必需文件缺失，**When** 建立版本，**Then** 明确报告文件、位置、原因并阻止该版本启用，不忽略错误后报告成功。
4. **Given** 同一有效资料集和相同处理设置，**When** 重复建立版本，**Then** 卡片标识、内容、来源和分类一致；运行时间等非内容记录可以不同。

### User Story 2 - 在连续聊天中稳定保持角色规则 (Priority: P1)

QQ 聊天用户继续通过既有文本入口交流，每轮回复都遵循当前角色身份、输出规范和情绪总则；普通问候不因未命中背景资料而被误判为不理解。

**Why this priority**: 常驻规则不能依赖资料检索命中，否则日常语气和行为边界会随问题措辞漂移。

**Independent Test**: 使用已核对的最小角色资料和替代外部服务，进行无检索命中、公共场合、未知场景及早期经历查询等对话，检查每轮实际采用的规则及回复结果。

**Acceptance Scenarios**:

1. **Given** 有效新版本已启用且用户发送普通问候，**When** 没有相关背景或示例，**Then** 角色仍可自然回应，常驻规则完整生效，不仅因相关资料为空就输出疑惑兜底。
2. **Given** 当前为高二、美羽毕业后且已是恋人，**When** 用户问及最初相识而命中早期敌意资料，**Then** 回复将其作为过去经历，不将当前关系退回敌对或未恋爱状态。
3. **Given** 用户没有提供称呼、忌口或共同纪念日，**When** 回复涉及这些话题，**Then** 不将示例、历史假设或待配置项编成用户事实。
4. **Given** 常驻资料缺失或不可用，**When** 处理聊天，**Then** 不冒充已遵循完整角色设定；使用既有受控失败路径并留下原因，不以无约束回复绕过就绪要求。
5. **Given** 资料检索或回复生成失败，**When** 本轮结束，**Then** 提供可诊断失败记录；通道可用时发送简短失败提示，不泄露凭据或冒充正常生成成功。

### User Story 3 - 依据场景和上下文使用完整参考卡 (Priority: P1)

聊天用户在被夸奖、吃醋、受伤、得到安抚等连续互动中，感受到符合条件的情绪变化；维护者能知道参考内容为什么被选中或排除。

**Why this priority**: 角色语气取决于关系、场景和情绪发展，不能仅凭相同关键词调用互相冲突的段落。

**Independent Test**: 给定已标注的上下文与公共／独处／未知场景，核对候选卡、排除理由、完整恢复机制及前后轮表现；这一选择流程可脱离 QQ 验证。

**Acceptance Scenarios**:

1. **Given** 同一关心话题分别发生于公共、独处和未知场景，**When** 选取参考，**Then** 独处限定的依赖或亲近表现只在满足条件时适用，未知不等于独处；公共场合仍可有内在情绪但外显收敛。
2. **Given** 近期上下文显示长期冷落后的真正受伤，**When** 用户继续谈论此事，**Then** 采用安静低落的完整规则，不因“吃醋”关键词一律升级为争吵。
3. **Given** 上一轮轻度吃醋且随后获得安抚，**When** 继续对话，**Then** 参考恢复机制逐步缓和，不每轮重新从触发阶段开始。
4. **Given** 一张高相关示例的场景不适用，**When** 选取参考，**Then** 排除该示例；适用条件不被相似程度覆盖。
5. **Given** 有适用示例，**When** 生成回复，**Then** 只参考表达风格，不把示例事件当成共同记忆，也不把示例中用户台词当成角色台词。
6. **Given** 条件歧义无法消除，**When** 选择规则，**Then** 使用常驻规则的保守表达并记录歧义，不随机拼接冲突卡。

### User Story 4 - 验证新版本并安全切换 (Priority: P2)

维护者可以比较重建前后资料覆盖和聊天表现，仅在新版本通过检查后启用，失败时继续使用原有效版本，并能恢复旧版本。

**Why this priority**: 更换资料来源不能中断已有聊天或把旧的验收结论误用在新资料上。

**Independent Test**: 准备两个可用版本和一个无效版本，分别执行构建失败、验收未通过、成功切换及恢复，检查各轮版本归属和业务数据保留。

**Acceptance Scenarios**:

1. **Given** 旧版本有效且正在服务，**When** 重建失败或新版本未通过验收，**Then** 旧版本继续有效，失败版本不会被隐式启用。
2. **Given** 新版本通过验收，**When** 切换，**Then** 一轮对话中的常驻规则、候选卡和来源使用同一版本，不混合新旧资料。
3. **Given** 已切换新版本，**When** 恢复之前仍满足启用条件的旧版本，**Then** 后续对话使用旧版本，用户历史、累计关系数据与发送记录不被清空。
4. **Given** 资料内容或处理设置改变，**When** 复用旧验收报告尝试启用，**Then** 拒绝并要求匹配新版本的验证结果。

### Edge Cases

- 相同标识出现在不同文件、元数据值为空或不认识的类型：报告具体位置并阻止启用，不静默合并或猜测类型。
- 新增不在已声明资料清单中的文件：明确列为未纳入；不得因为放在目录内就自动成为角色约束。
- 卡片超出处理或对话容量：报告受影响卡片及限制，阻止不完整版本启用；不得静默截断、机械拆散或遗漏恢复机制。
- 多轮示例中的角色续行没有重复说话者标签：仍属于上一角色，不能被当作独白或另一用户发言。
- 检索为空但话题普通：继续受规则约束的自然交流；问到资料未提供的具体事实：承认未知或请求澄清，不补造。
- 当前关系状态与本资料包恋人限定冲突：不修改累计好感或强行覆盖会话状态；排除恋人专属卡并提供可诊断的资料包不适用提示。
- 先前情绪与新刺激冲突、或两张卡均适用：遵循来源明确的条件与例外，保留必要组合；无法消歧时使用保守表达。
- 检索材料含有操作指令或要求忽略角色规则：作为资料处理，不执行系统操作，也不提升为常驻约束。
- 新包没有明确心理独白素材：保持该能力禁用，不将无说话者的规则、说明、动作或示例续行误当素材。
- 切换期间有已开始的回复：本轮继续使用开始时的完整版本，后续轮次采用新版本。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须以 `doc/乾纱凪角色设定整理版/` 中明确声明的六份内容文件 01 至 06 作为新资料包来源；00 为加载说明，07 为维护记录；两者不得进入角色生成内容，原始 Word 保留为追溯资料，不与新资料重复混入同一版本。
- **FR-002**: 系统必须完整加载 01 核心设定、02 输出规范和 03 状态总则，使其每轮生效，不依赖相关性命中；必需常驻材料不全的版本不得启用。（验收：故事1.1、2.1、2.4）
- **FR-003**: 系统必须将 03 至 06 的有标识章节视为完整资料卡，保留标识、类型、角色、原文引用、适用范围和正文；吃醋三级与恢复机制、多轮对话示例均不得拆散。（验收：故事1.2、3.2、3.3、3.5）
- **FR-004**: 系统必须分别保留常驻规则、情绪、场景行为、背景、外貌、档案和示例的用途；无说话者内容不能据此被自动认定为心理独白。（验收：故事1.1、1.2与无独白边界用例）
- **FR-005**: 系统必须验证必需文件、必要字段、类型和标识唯一性，明确报告错误位置及未纳入文件；任何必需卡片处理失败均阻止版本启用。（验收：故事1.3及导入边界用例）
- **FR-006**: 每份来源及每张卡必须可以追溯到本次读取的文件版本、文件内标题与位置，以及整理材料记载的原始来源；不得将未核验的原作归属或新增示例标成已核验原作事实。（验收：故事1.1、1.4）
- **FR-007**: 相同资料内容和相同处理设置重复导入必须得到一致的逻辑卡片及内容归属；处理过程不得静默截断、改写或丢弃资料。（验收：故事1.4及容量边界用例）
- **FR-008**: 选取情绪、场景卡和示例必须结合当前消息、近期上下文、上一轮有效情绪、关系和场景；未确认条件保持未知，不得仅按关键词或相关程度满足条件。（验收：故事3.1至3.4）
- **FR-009**: 公共、独处、未知必须被区分；公共场合限制外显，不等于清除情绪；未知场景不得触发独处限定的亲近行为。（验收：故事3.1）
- **FR-010**: 系统必须保留触发、升级、例外及恢复条件，支持安抚后的缓和和受伤后的安静，不把负面情绪强度等同于越来越尖锐。（验收：故事3.2、3.3）
- **FR-011**: 规则协调必须先满足输出规范与用户行动自主权，再检查关系及场景，再使用有效情绪和场景参考；示例不得覆盖约束，历史背景不得改变当前故事阶段。（验收：故事2.2、3.4至3.6）
- **FR-012**: 示例必须保留说话者、轮次、适用条件及新增或改写性质，只用于表达参考；不得转成用户事实、共同经历或强制复读台词。（验收：故事1.2、3.5及续行边界用例）
- **FR-013**: 对没有命中补充资料的普通闲聊，系统必须继续基于有效常驻设定回应；对来源没有提供的具体事实保持未知，歧义无法消除时请求澄清或保守表达。（验收：故事2.1、2.3、3.6）
- **FR-014**: 同居状态、恋人称呼、纪念日、精确年龄及用户偏好等未定义内容不得从资料标题、示例或模型猜测确认为事实；用户与会话之间不得串用此类信息。（验收：故事2.3及双用户隔离用例）
- **FR-015**: 本资料包默认适用整理版指定的高二恋人时间线；系统必须识别与会话关系不匹配的情况，不为适配资料而修改用户的累计关系数据。（验收：关系冲突边界用例）
- **FR-016**: 角色回复必须使用第一人称、保留用户行动和台词自主权、句末无句号、允许纯台词且不强制动作组合；文字聊天不得默认双方处于同一物理地点。（验收：输出验证集及故事2.1）
- **FR-017**: 系统必须向维护者提供导入覆盖、选中与排除卡片、判断条件、歧义、当前版本和失败原因的可核对记录；不得泄露凭据。（验收：故事1.3、2.5、3.4、3.6）
- **FR-018**: 重建必须先产生待验收版本，不直接覆盖活动版本；只允许完整且通过对应版本检查的资料包启用，旧验收结论不得冒用于变化后的资料或处理设置。（验收：故事4.1、4.4）
- **FR-019**: 版本切换必须保证每轮资料一致，支持恢复仍合格的旧版本，且不清空用户历史、关系累计和消息发送记录。（验收：故事4.2、4.3及切换边界用例）
- **FR-020**: 新资料没有独白素材时必须明确禁用独白能力，但不得阻止已通过验收的普通聊天启用；不因本功能新增平台主动消息能力。（验收：无独白边界用例）
- **FR-021**: 新资料必须用于既有 QQ 文本对话链路，并能脱离 QQ 独立核对；资料选取、生成和发送失败必须分别可诊断，保留现有消息去重、会话隔离、发送限制及隐私边界。（验收：故事2.5、4.3及双用户、重复消息、发送失败用例）
- **FR-022**: 启用前必须提交资料完整性结果、条件筛选结果和角色对话评估；替代服务验证与真实服务验证分开记录，未执行不得标为通过。（验收：故事4.1、4.4和全部成功标准）

### Key Entities *(include if feature involves data)*

- **角色资料包**：某一版声明的来源集合、角色及故事阶段、常驻材料、参考卡、完整性状态和启用资格。
- **来源文件版本**：实际文件、内容版本、标题与位置、原始来源说明；区分整理新增与原文信息。
- **资料卡**：稳定标识、用途类型、角色、完整正文、适用条件、触发与恢复信息、来源。
- **会话条件**：所属用户、关系阶段、公共／独处／未知场景、交流媒介、有效情绪及有依据的用户事实；未知可显式保留。
- **本轮资料选择记录**：固定版本、常驻材料、选中与排除的卡片、理由及歧义；与本轮对话关联。
- **验收与切换记录**：被检查的资料和处理设置、实际执行结果、启用与恢复记录，不与业务关系账本混淆。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 当前整理版的两份完整常驻文件及全部 26 张有标识卡片得到 100% 覆盖和来源追溯；其中 1 张状态总则常驻，另 25 张按用途归类；00 和 07 的对话内容泄入数量为 0。
- **SC-002**: 重复导入同一输入两次，全部逻辑标识、正文和用途归属一致；重复标识、缺失字段、缺失文件、超出容量四类故障用例全部被明确拒绝，旧版本均保持有效。
- **SC-003**: 至少 36 个事先标注预期适用卡的参考选择用例（覆盖六张情绪卡、六张场景卡、六张背景资料卡和七张示例）中，至少 90% 找到预期参考；另设至少 12 个场景或关系不匹配负例，不合条件卡被采用次数为 0。预期集合在执行前固定，不能根据结果追改。
- **SC-004**: 至少 24 个普通交流用例在补充资料未命中时，至少 23 个仍获得与话题相关的角色回复；不得因没有示例而统一声称不理解。
- **SC-005**: 采用整理记录中的 12 类行为场景，每类两段至少三轮的固定对话，共 24 段，按各场景通过标准评审，至少 22 段通过；其中公共／未知场景擅自亲近、代写用户行动或台词、将示例冒充共同记忆、跨用户引用事实四类严重错误为 0。
- **SC-006**: 对 SC-005 的全部角色回复逐条检查，第一人称、自主权和句末标点要求全部通过；普通日常不要求反转否认，至少 80% 普通日常回复不使用“关心后立即否认”的固定结构。
- **SC-007**: 构建失败、未验收启用、成功切换、处理中切换、恢复旧版五类演练全部达到预期；每轮混用新旧资料次数为 0，用户历史、关系和发送记录丢失数量为 0。
- **SC-008**: 维护者依据单轮诊断，可在 3 分钟内定位该轮资料版本、实际采用来源、排除理由或失败阶段；以至少 5 个事先准备的不同问题各验证一次，全部完成。

## Assumptions

- 本轮交付是功能规格及质量检查；实际重建、模型调用、校准和切换在后续规划、任务及实施阶段执行。
