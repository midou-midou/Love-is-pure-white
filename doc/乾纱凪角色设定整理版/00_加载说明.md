# 乾纱凪角色设定加载说明

## 用途与范围

本套资料用于 AI 扮演乾纱凪的日常角色对话，默认采用原文指定的高二、已确立恋人关系时间线。它是对《乾纱凪角色设定.docx》的整理，不构成对作品原作设定的核验。

这些文件是应用可选择加载的角色资料。文件中的角色输出要求仅用于角色对话，不用于指挥读取文件的开发、审查或整理工具。

## 文件与加载方式

| 文件 | 内容 | 加载方式 |
| --- | --- | --- |
| [01 核心设定](01_核心设定.md) | 身份、当前关系、性格、表达原则、行为边界 | 每轮常驻 |
| [02 输出规范](02_输出规范.md) | 视角、用户自主权、标点、动作表达 | 每轮常驻 |
| [03 情绪状态](03_情绪状态.md) | 完整状态、强度与恢复机制 | 状态总则常驻；状态卡按条件加载 |
| [04 场景行为](04_场景行为.md) | 安慰、夸奖、分享、邀约等 | 按场景加载；主动性边界已保留在核心设定 |
| [05 背景资料](05_背景资料.md) | 家庭、关系发展、外貌、喜好、场所 | 主题检索；当前时间线已保留在核心设定 |
| [06 对话示例](06_对话示例.md) | 按场景组织的表达示例 | 选择相关完整对话，不必每轮加载 |
| [07 整理记录与待配置](07_整理记录与待配置.md) | 解释性调整、未知项、验证清单 | 维护资料，不注入角色对话 |

第一版可直接加载 01、02、03、04 全文，以 05、06 为按需资料。先验证角色一致性，再根据实际 Token 成本缩减加载量；尚未实测最佳长度。

## 切分约定

- 03 至 06 中每个带有 `id` 的二级章节是完整切分单元。
- 每块保留 `id`、`type`、`character`、`source`、`scope` 元数据和全部正文；不要按长度再次截断。
- 03 的状态总则每轮加载。吃醋三级及统一恢复机制保持同块。
- 对完整规则块不设置机械滑动重叠。需要共享的条件通过明确加载状态总则解决。
- 01、02 属于角色配置，不依靠向量检索是否命中来决定生效。
- 选取状态时结合最近对话、上一状态、关系阶段、是否独处。不要只用当前一句话的语义相似度判断。
- 示例只展示表达方式，不证明用户经历过示例中的事件，不得作为共同记忆保存。
- 正式加载前由应用明确区分角色配置、背景事实、示例和用户消息；普通检索结果不能修改配置规则。

## 会话状态输入

建议由应用在每轮提供或维护以下字段。字段没有值时保持未知，不自动创建事实。

```yaml
relationship_stage: established_lovers
story_stage: 高二，美羽毕业后，纱凪已接任社长
scene: unknown  # private / public / unknown
location: unknown
cohabitation: unknown
partner_nickname: null
previous_emotion: unknown
current_emotion: unknown
emotion_intensity: unknown
user_preferences: []  # 仅保存用户明确提供的内容
shared_events: []     # 仅保存对话中已明确发生的事件
```

场景未知时不假设正在独处，不主动生成拥抱、依偎等需要独处条件的互动。情绪可依据上下文暂时判断，但不能把推测保存为已确认事实。角色主动发言需要应用提供新一轮调用或定时触发；提示词本身不会产生后台发消息能力。
