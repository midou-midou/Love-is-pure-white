# 乾纱凪 VRM 1.0 模型制作计划

## 1. 项目目标

使用 Blender 创建一套保留参考立绘二次元观感的乾纱凪全身 3D 模型，完成骨骼、蒙皮、面部表情、口型、视线、头发和服装物理，并导出可由手机 App 与现代网页运行时直接加载的 VRM 1.0 文件。

最终模型采用标准 T-Pose、Y-Up、面向 Z+，以单个 `.vrm` 文件作为跨端主交付物。

## 2. 交付内容

- `inui_sana_master.blend`：保留建模、材质、骨骼、Shape Key 与物理设置的 Blender 源文件。
- `inui_sana_mobile.vrm`：手机和网页共用的 VRM 1.0 优化版。
- `textures/`：Base Color、阴影控制、法线、遮罩等源贴图。
- `preview/`：正面、侧面、背面、表情和动作预览图。
- `licenses/README.md`：作者、用途、署名、再分发及商用权限说明。
- `qa/model-validation.md`：VRM 校验、性能数据以及手机与网页验收结果。

## 3. 技术基线与性能预算

| 项目 | 目标 | 上限 |
|---|---:|---:|
| 三角面数 | 35,000–55,000 | 70,000 |
| Skinned Mesh Renderer | 4–8 | 10 |
| 材质数量 | 4–6 | 8 |
| 单顶点骨骼影响 | 不超过 4 | 4 |
| 骨骼总数 | 90–130 | 150 |
| 主纹理 | 2 张 2048² | 3 张 2048² |
| 辅助遮罩/法线 | 1024² | 2048² |
| VRM 文件体积 | 12–25 MB | 35 MB |
| Web 首次可交互 | 中端手机 Wi-Fi 下 3 秒内 | 5 秒 |
| 渲染目标 | 中端手机稳定 30 FPS | 不低于 24 FPS |

移动端版本不启用超过 4 个骨骼权重，不导出灯光和无关动画，避免依赖 VRM 高级导出选项，以获得最大的 App 与浏览器兼容性。

## 4. 制作阶段

### 阶段 A：角色设定与比例锁定

1. 导入现有正面立绘作为 Blender 正交参考。
2. 绘制侧面和背面设定，补全原图不可见区域：后脑、马尾根部、制服背面、裙后片、鞋底。
3. 锁定身高比例、头身比、五官位置、发型轮廓和服装结构。
4. 输出正/侧/背三视图，确认后进入建模，避免后续大范围返工。

验收：三视图轮廓一致，正面与原立绘的脸型、眼距、发色、侧马尾、黑色大蝴蝶结和蓝色领结保持一致。

### 阶段 B：低模与拓扑

1. 从头部、躯干和四肢建立对称基础网格。
2. 面部采用适合表情变形的环线：眼眶、嘴唇、鼻翼和下颌保持连续拓扑。
3. 身体在肩、肘、腕、髋、膝、踝增加变形环线。
4. 服装独立建模：上衣、领口、领结、袖子、百褶裙、长袜、鞋。
5. 头发按运动分组：后发、刘海、左右侧发、呆毛、马尾根部、马尾主体、编发、尾端和丝带。
6. 删除身体被服装永久遮挡的不可见面，降低穿模和面数。

验收：无非流形、无重叠面、法线统一；关节处具备足够环线；轮廓在手机远景仍清晰。

### 阶段 C：UV 与材质贴图

材质采用 VRM 1.0 MToon，确保 Unity 和 Three.js 端呈现一致的二次元明暗。

建议材质分组：

1. `M_FaceBody`：脸、耳、脖子、手和腿。
2. `M_EyesMouth`：眼白、虹膜、高光、眉毛与口腔。
3. `M_Hair`：刘海、后发、马尾和编发。
4. `M_Uniform`：上衣、裙子、长袜和鞋。
5. `M_Accessories`：头部蝴蝶结、蓝色领结和马尾丝带。

贴图内容：

- Base Color：直接绘制颜色、局部渐变和必要的固有阴影。
- Shade Color：为 MToon 设置冷紫灰服装阴影和深莓红头发阴影。
- Normal：仅用于衣褶、编发和鞋面等需要细节但不值得增加几何的位置。
- Mask：合并金属度、光泽或局部高光控制，减少纹理采样。
- Emission：仅保留眼睛高光的轻微增强，避免移动端过度发光。

颜色管理使用 Standard 视图进行 VRM 外观核对。透明材质只用于必要的发梢或眼睫，优先 Alpha Clip，减少移动端透明排序问题。

验收：Blender、Unity 与网页截图的主色、阴影边界和轮廓线观感接近；无明显 UV 接缝、拉伸或透明排序错误。

### 阶段 D：Humanoid 骨骼与蒙皮

建立符合 VRM 1.0 Humanoid 的必需骨骼：

- `hips` → `spine` → `chest` → `upperChest` → `neck` → `head`
- 左右 `shoulder` → `upperArm` → `lowerArm` → `hand`
- 左右 `upperLeg` → `lowerLeg` → `foot` → `toes`
- 完整手指链：thumb、index、middle、ring、little
- 左右眼骨骼：`leftEye`、`rightEye`
- 可选 `jaw`

辅助骨骼：

- 刘海 3–5 链、侧发左右各 2–4 链。
- 后发 4–6 链。
- 侧马尾从根部到发梢分 4–6 段，编发单独 3–5 段。
- 大蝴蝶结左右各 2–3 段，蓝色领结与长丝带各 2–3 段。
- 裙摆按前、后、左、右划分 8–12 条短链。

绑定顺序：自动权重作为初稿 → 手工清理权重 → 关节极限姿势测试 → 镜像与归一化 → 限制每顶点最多 4 个骨骼影响。

验收动作：深蹲、抬腿、手臂前举/侧举、双手抱胸、转头、低头和坐姿。不得出现肩部塌陷、肘膝尖锐折叠、裙腰分离或明显穿模。

### 阶段 E：脸部表情、口型与视线

以 Shape Keys 制作 VRM 1.0 标准表情：

- 眨眼：`blink`、`blinkLeft`、`blinkRight`
- 口型：`aa`、`ih`、`ou`、`ee`、`oh`
- 情绪：`happy`、`angry`、`sad`、`relaxed`、`surprised`
- 附加：微笑、害羞、疑惑、闭眼笑、流泪，可映射为自定义 Expression

眼球视线优先采用眼骨骼 LookAt，以获得较低运行成本；限制水平与垂直旋转，防止虹膜穿出眼眶。口型 Shape Key 必须包含嘴唇、口腔和下颌的协调变化，不能只缩放嘴部贴图。

验收：每个表情单独和混合播放都不破面；眨眼完全闭合；五元音可由麦克风音量或音素驱动；视线极限不露出眼球边缘。

### 阶段 F：SpringBone 与碰撞体

为长发、马尾、编发、呆毛、蝴蝶结、领结丝带和裙摆配置 VRM SpringBone。头部、胸部、肩部、背部和髋部设置碰撞体。

调校原则：

- 马尾根部刚度高，发梢阻尼低，体现长度和重量。
- 编发比散发更硬，摆幅更小。
- 蝴蝶结与领结响应快但幅度小。
- 裙摆只做轻微跟随，不模拟布料级大幅运动。
- 物理链之间避免互相穿透和高频抖动。

验收：30/60 FPS 下表现一致；快速转身后能自然收敛；静止时无持续抖动；头发不穿过脸、肩和胸部。

### 阶段 G：VRM 1.0 配置与导出

1. 使用 VRM Add-on for Blender 配置 Humanoid 骨骼映射。
2. 设置 Expressions、LookAt、First Person、SpringBone 与 MToon。
3. 填写模型标题、作者、版本和许可信息。
4. 以 T-Pose、Z+ 朝向、米制单位导出 VRM 1.0。
5. 不导出灯光、相机、控制器骨骼和 Blender 专用修改器。
6. 将贴图嵌入 `.vrm`，保证单文件运行时加载。

验收：重新导入 Blender 后骨骼、材质、表情和物理均存在；VRM Validator 无阻断错误。

### 阶段 H：手机 App 验收

建议基准客户端使用 Unity 2022.3 LTS 或更高版本与当前 UniVRM：

1. Android 真机：中端设备和一台低端设备。
2. iOS 真机：至少一台仍受目标系统支持的普通机型。
3. 测试运行时异步加载、待机动画、眨眼、口型、视线、全身动作和 SpringBone。
4. 记录加载时间、峰值内存、稳定帧率、发热和切后台恢复。
5. 确认 IL2CPP 构建、资源释放和重复加载不会泄漏内存。

通过标准：模型可由本地文件或 URL 加载；连续运行 20 分钟无崩溃；目标设备保持 30 FPS；卸载模型后纹理与 Mesh 内存可回收。

### 阶段 I：网页验收

网页基准采用 Three.js、GLTFLoader 与 `@pixiv/three-vrm`：

1. 验证 Chrome、Safari 和 Edge 的桌面与移动端版本。
2. 支持拖拽/URL 加载、Orbit 控制、待机动作、表情切换、眨眼和 SpringBone。
3. 使用 gzip/Brotli、HTTP 缓存与加载进度展示。
4. 视设备能力使用 WebGL；WebGPU 作为可选增强，不作为唯一运行路径。
5. 页面离屏或进入后台时暂停渲染循环。

通过标准：无控制台错误；材质、透明、轮廓和物理与 Unity 基准基本一致；触屏旋转缩放正常；模型销毁后 GPU 资源得到释放。

## 5. 质量检查清单

- 角色轮廓、发型、配色、服装与参考设定一致。
- 模型处于标准 T-Pose，比例单位正确，朝向 Z+。
- VRM 1.0 Humanoid 必需骨骼映射完整。
- 所有权重归一化，单顶点不超过 4 个骨骼影响。
- 面部拥有眨眼、五元音、基础情绪和稳定视线。
- MToon 在 Blender、Unity、Web 三端外观接近。
- SpringBone 有合理碰撞体，无静止抖动和严重穿模。
- 文件体积、面数、材质和纹理不超过移动端预算。
- VRM 元数据和再分发权限填写完整。
- Android、iOS 和移动浏览器完成真机验收。

## 6. 预计排期

| 阶段 | 预计工作量 |
|---|---:|
| 三视图与比例锁定 | 1–2 天 |
| 建模与拓扑 | 4–7 天 |
| UV、材质与贴图 | 3–5 天 |
| 骨骼、蒙皮与姿势修正 | 3–5 天 |
| 表情、口型与视线 | 2–4 天 |
| SpringBone 与碰撞 | 1–2 天 |
| VRM 导出与跨端优化 | 2–3 天 |
| 手机、网页测试与修正 | 2–4 天 |
| 合计 | 18–32 个工作日 |

排期按一名有经验的角色建模师估算。若增加高精度手部、可换装、更多表情、ARKit 52 表情或多档 LOD，需要单独增加工期。

## 7. 开工前需要锁定的事项

1. App 中主要呈现半身还是全身。
2. 是否需要动作捕捉，以及目标方案是 ARKit、MediaPipe 还是普通音量口型。
3. 是否需要换装、脱帽/拆蝴蝶结或其他可切换部件。
4. 模型是否公开下载或用于商业发布，以便正确填写 VRM 许可元数据。
5. 是否接受对侧面与背面进行符合现有设计语言的补完。

默认实施方案：全身模型、VRM 1.0、MToon、标准 VRM 表情、眼骨骼 LookAt、头发与服装 SpringBone、单一移动端优化规格，不包含换装与 ARKit 52 表情。
